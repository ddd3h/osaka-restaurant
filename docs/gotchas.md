# 踏んだ罠

実際に事故ったものだけを、症状 → 原因 → 対処の順で残す。
どれも「エラーが出ないまま静かに壊れる」種類なので、同じ形を見たら真っ先にここを疑う。

---

## 1. maplibre-gl v6 では地図が真っ白になる

**症状** — 地図の領域が完全に白いまま。コンソールにエラーは1本も出ない。
属性表示（`OpenFreeMap © OpenMapTiles`）とズームボタンは出るのに、タイルだけ出ない。

**調べて分かったこと**

- スタイル JSON・TileJSON・スプライトの取得は**すべて 200 で成功**していた
- なのに `load` イベントが発火せず、**ベクタタイルのリクエストが1本も飛ばない**
- `map._frameRequest === null` で描画ループが止まっていた。
  `triggerRepaint()` も `resize()` も効かない
- Web Worker は起動していて、例外も投げていない
- **React も自前 CSS も無い最小 HTML でも再現**した（＝アプリ側の問題ではない）
- 同じページで **v5.24.0 に落としたら即座に描画された**

**対処** — `maplibre-gl` は **v5 系に固定**（`^5.24.0`）。

上げるときは `npm test` が通るだけでは不十分。**実ブラウザで地図が描画されることを
必ず目視すること。** タイルが出ないバグはテストでは捕まらない。

## 2. ピンの CSS を marker のルート要素に当てると、1本ずつ下にずれる

**症状** — ピンが地図上の正しい位置に立たない。
しかも「1本目は合っているのに、後のピンほど下にずれる」という不思議な壊れ方。

**原因** — maplibre はマーカーのルート要素（`.maplibregl-marker`）に
`position: absolute` と座標の `transform` を載せている。
そこへ CSS Modules 側の `.pin { position: relative }` をぶつけていた。
CSS Modules のほうが後に読まれるので**勝ってしまい**、マーカーが通常フローに戻って
**1本ごとに要素の高さぶん（当時52px）下に積み上がっていた**。

**確認できた証拠** — 最北の店（3番目に描画）が y=216 → `216 − 52×3 = 60`。
最南の店（2番目）が y=805 → `805 − 52×1 = 753`。
どちらも `fitBounds` のパディング境界（60 と 813−60）にぴったり一致した。

**対処** — ピンの見た目は**必ず marker 要素の「中の」ボタンに持たせる**。
ルートは素の `<div>` のままにして、自前のスタイルを一切当てない。

```ts
const root = document.createElement('div')   // ← maplibre の持ち物。触らない
root.appendChild(button)                     // ← 見た目はこっち
new Marker({ element: root, anchor: 'center' })
```

`transform` も同じ理由で危ない。ホバー時の `transform: scale()` をルートに当てると、
maplibre の座標指定を上書きしてピンが画面の隅へ飛ぶ。

あわせて、maplibre がルートに付ける `role="button"` / `aria-label="Map marker"` は
中の本物のボタンと二重に読み上げられるので、生成後に外している。

## 3. 共有リンクを開くと、その店ではなく全体表示に戻る

**症状** — `#/r/<id>` を直接開くと一瞬その店へ寄るのに、すぐ全店が入る画角に戻る。

**原因** — 選択時の `flyTo` の直後に、絞り込み結果に合わせる `fitBounds`
（200ms のデバウンス付き）が走って上書きしていた。

**対処** — **初回の1回だけ**、既に店が選択されていれば `fitBounds` を飛ばす。
判定は map インスタンスを ref に覚える方式にした。
React StrictMode の二重マウントでは map インスタンスも作り直されるので、
「新しい map かどうか」で見れば dev でも本番でも一度きりになる。

## 4. その他、小さいもの

- **画像の URL は必ず `assetUrl()` を通す。** GitHub Pages ではサイトが
  `/<リポジトリ名>/` 配下に載るので、`/photos/x.jpg` と書くと 404 になる。
  ただし `src/photos/` の写真は **Vite が解決済み**なので通してはいけない（二重前置になる）。
- **モバイルの検索欄は 16px 以上。** それ未満だと iOS Safari がフォーカス時に
  画面を勝手に拡大する。
- **`import.meta.glob` はビルド時に確定する。** dev 起動中に `src/photos/` へ
  フォルダを足しても反映されないことがある。反映されなければ dev を再起動する。
- **CSS Modules から関数を export しない。** `TagChip.tsx` から `chipStyle()` を
  export していたら oxlint の `react/only-export-components` に引っかかった
  （Fast Refresh が効かなくなる）。別ファイルへ切り出した。
