# お店データ（`src/data/restaurants.json`）

データはこの1ファイルだけ。1件足せば**地図のピン・リストのカード・タグのチップ・
検索対象**がまとめて増える。バックエンドもビルド設定の追記も要らない。

## 全フィールド

```jsonc
{
  "id": "wanaka-sennichimae",     // 必須。半角小文字英数とハイフンのみ。URL に載る
  "name": "たこ焼道楽 わなか 千日前本店",  // 必須
  "kana": "たこやきどうらく わなか",       // 任意。入れると かな/カナ 検索が強くなる
  "emoji": "🐙",                   // 必須。写真が1枚も無いときだけ使う代替アイコン
  "tags": ["粉モン", "大阪ぽい"],    // 必須（空配列も可）。そのままフィルターのチップになる
  "area": "難波",                  // 必須。カードのバッジに出る。検索対象にも入る
  "lat": 34.66525,                // 必須。大阪府の範囲内（34.2〜35.0）
  "lng": 135.5026,                // 必須。大阪府の範囲内（135.0〜135.8）
  "comment": "ここが主役。紹介文。", // 必須。検索対象にも入る
  "photo": "photos/wanaka.jpg",   // 任意。写真1枚だけの店に使うフォールバック
  "budget": "¥500〜1,000",         // 任意。そのまま文字列で表示するだけ
  "rating": 3.66,                 // 任意。食べログの点数。スクリプトが書くので手で触らない
  "address": "大阪市中央区…",       // 任意。検索対象にも入る
  "hours": "10:00〜21:00",         // 任意
  "url": "https://…",             // 任意。「お店のページ」ボタンのリンク先
  "mapUrl": "https://…"           // 任意。省略時は lat/lng から Google マップを開く
}
```

必須は **`id` / `name` / `emoji` / `tags` / `area` / `lat` / `lng` / `comment`** の8つ。
型定義は `src/types.ts` の `Restaurant`。

**配列の順 = 「おすすめ順」**。並び替えの既定値がこの順なので、推したい店は上に置く。

## 食べログ点数（`rating`）の更新

```bash
npm run ratings            # 全店ぶん取り直して書き戻す
npm run ratings -- --check # 差分があるかだけ見る（書かない）
```

- `rating` は**機械が書くフィールド**。手で数字を入れない（次回実行で上書きされる）。
- 対象は `url` が `https://tabelog.com/` で始まるレコードだけ。食べログにページが無い店は
  `rating` を持たず、★も出ないし「食べログ点数順」では末尾に沈む。
- 取得に失敗した店は**既存の値を残す**。ページ構造が変わった程度で正しい点数を消さないため。
- 書き戻しは既存の整形を保つこと。`JSON.stringify(x, null, 2)` で書くと `tags` が全部
  展開されて全行が差分になる。`scripts/lib/tabelog.mjs` の `formatRestaurantsJson()` を使う
  （同梱データを1バイトも変えずに round-trip できることをテストで固定してある）。
- 新しい店を足したら忘れずに一度回す。回さないと ★ が付かないまま公開される。

## id の決まり

- `^[a-z0-9-]+$` のみ。日本語・大文字・スペースは通らない。
- **共有URLに載る**（`#/r/wanaka-sennichimae`）ので、一度公開したら変えないほうがいい。
  変えると前に配ったリンクが「見つかりませんでした」になる。
- `src/photos/<id>/` のフォルダ名とも一致させる必要がある（→ [photos.md](./photos.md)）。

## タグ

**自由記述**。決められた一覧は無く、JSON に書いたタグがそのままチップになる。

- 色は**タグ文字列のハッシュから自動決定**（`src/lib/tagColor.ts`）。同じタグは常に同じ色。
- 表記ゆれ（`粉モン` と `粉もん`）は**別タグ扱い**になるので揃えること。
- チップの数字は「そのタグを足したら何件残るか」。0 になる組み合わせは薄く表示される。
- 複数選択は **AND**（絞り込みが目的なので）。

## 座標の調べ方

Google マップで店を右クリック →「この場所について」に出る数値が `緯度, 経度` の順。
**左が `lat`、右が `lng`**。

## 壊れたデータの扱い

`src/data/loadRestaurants.ts` の `validate()` が読み込み時に検査し、
問題のあるレコードは**読み飛ばして `console.warn` を出す**（サイト全体は落とさない）。

弾かれる条件:

- 必須フィールドが空、または文字列でない
- `id` が `^[a-z0-9-]+$` に合わない
- `id` が重複（**先に書いたほうが勝つ**）
- `tags` が文字列配列でない
- `lat` / `lng` が数値でない、または大阪府の範囲外
- `rating` が 1〜5 の数値でない（レコードごと落ちる。無い分にはかまわない）

思ったより件数が少ないときは、ブラウザのコンソールを見ると理由が出ている。

## 検索のしくみ

読み込み時に `name + kana + tags + area + comment + address` を連結し、
`normalize()`（NFKC → カタカナをひらがなへ → 小文字化）をかけた `searchIndex` を作る。
検索語も同じ関数を通すので、**「たこやき / タコヤキ / ﾀｺﾔｷ」がすべて同じ結果**になる。

スペース区切りは AND。`kana` を入れておくと、漢字表記の店をかな入力で引ける。
